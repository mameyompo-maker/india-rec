# India Rec — NBF (Tanheia) 26 圃場測定アプリ

モザンビークの現場作業者がスマホで Jatropha の測定値を登録し、Google スプレッドシート
[NBF(Tanheia)26](https://docs.google.com/spreadsheets/d/1WSfQdkMdy_cton-Za6TGzRmpSi1cjycWqHfMCS_cDXQ/edit)
の `Data` シートに書き込むための **完全オフライン対応 PWA**。UI はすべてポルトガル語。

JatLog(Streamlit)とは別アプリ。Streamlit はサーバーとの常時接続が前提のため、
圏外では操作そのものが止まる。本アプリはその制約を回避するために静的 PWA として作った。

## 構成

```
端末(PWA / GitHub Pages)
  ├ Service Worker …… アプリ本体を端末にキャッシュ → 圏外でも起動する
  ├ IndexedDB     …… 送信待ちキュー + 送信済み履歴
  └ 端末時刻       …… 「保存」を押した瞬間の時刻を記録(送信時刻ではない)
        │  電波が来たら自動で POST
        ▼
Google Apps Script(ウェブアプリ)
  ├ 共有トークンで認証
  ├ 送信IDで重複排除(再送しても二重登録されない)
  ├ Data シートへ書込(空欄は書かない = 既存値を消さない)
  └ Log シートへ1行追記(誰が・いつ・何を)
```

## ファイル

| パス | 中身 |
|---|---|
| `docs/` | GitHub Pages で配信する PWA 一式 |
| `docs/config.js` | **Apps Script の URL をここに貼る** |
| `docs/i18n.js` | 画面の文言(ポルトガル語・英語・日本語) |
| `docs/plants.json` | 415株のマスタ(自動生成物。列ごとの蛇行の向きも持つ) |
| `docs/sw.js` | Service Worker。**変更時は `CACHE` の値を上げる** |
| `apps_script/Codigo.gs` | スプレッドシート側に貼るコード |
| `tools/gen_plants.py` | `plants.json` の生成 |
| `tools/gen_icons.py` | アイコンの生成 |

## セットアップ手順

### 1. Apps Script を配置(Kaz さん作業)

1. スプレッドシートを開き **拡張機能 → Apps Script**
2. 既定の `Code.gs` の中身を全部消し、`apps_script/Codigo.gs` を貼り付けて保存
3. 左の歯車 **プロジェクトの設定 → スクリプト プロパティ** で2つ追加
   - `TOKEN` … 現場端末に入力する「Código de activação」。**未設定だと既定値 `jatropha`**
     (JatLog と共通、Kaz さん指定)。長い文字列に変えたい場合はここで上書きする
   - `ADMIN_PASSWORD` … 管理者モードのパスワード。**未設定だと既定値 `IndiaRec2026` になる**ので、
     必ず設定すること
4. 右上 **デプロイ → 新しいデプロイ → 種類:ウェブアプリ**
   - 説明: `India Rec v1`
   - **次のユーザーとして実行: 自分**
   - **アクセスできるユーザー: 全員**
   - デプロイ → 初回は権限の承認画面が出る(「詳細」→「安全ではないページに移動」で進む)
5. 表示される **ウェブアプリの URL**(`.../exec` で終わる)を控える

> ⚠ コードを直したときは「デプロイを管理 → 編集(鉛筆)→ バージョン:新バージョン → デプロイ」。
> 「新しいデプロイ」を選ぶと URL が変わってしまい、配布済みの端末が繋がらなくなる。

### 2. URL をアプリに設定

`docs/config.js` の `ENDPOINT` を、手順1で控えた URL に差し替える。

### 3. GitHub Pages で配信

リポジトリを作り、Settings → Pages → Source を `main` ブランチの `/docs` に設定。
発行された URL を現場のスマホで開く。

### 4. 端末ごとの初期設定(1回だけ)

1. スマホのブラウザで Pages の URL を開く
2. ブラウザメニューから **「ホーム画面に追加」**(これをしないとオフラインで起動しない)
3. 起動 → `Código de activação` に手順1の `TOKEN` を入力
4. 名前を入力して完了

以降は圏外でもホーム画面のアイコンから起動できる。

## 現場での使い方

1. **Que levantamento vai fazer?** — 調査の種類を選ぶ
   - **Crescimento** … 高さ・樹冠・枝数・cachos(G〜M列)。半年ごとの定期調査
   - **Descritores morfológicos** … 形態記載(N〜Z列)
2. Crescimento の場合は **Ronda**(調査回)を入力。端末に記憶されるので毎回は不要
3. **列(r01〜r16)を選ぶと番号に `1` が入る**ので、そのままテンキーで
   **列の中での番号**を打つ(= シートの **D列「No. in row」**)
   → 株が決まると、**いちばん大きい行に「その株の系統」**が出る:
     `2 (India #bag02)  n.º 15`(= 系統2番、その中の15株目)。
     **データシートと圃場の地図が系統で並んでいる**ので、これが読めれば照合できる
   → その下に Plant ID、さらに `Fileira r02, n.º 10` と蛇行の向き
     (`→ n.º 1 à esquerda` / `← n.º 1 à direita`。奇数列は左端から、偶数列は右端から)
   → 系統の先頭の株には **`início da linhagem`** の印が付く
   → 枯れている株は右下の小さな **`Marcar planta morta`** で印を付ける(下記)
   → **この画面はスマホ1画面に収まる。**「Continuar」は下に固定してあるので、
     探して指でスクロールする必要はない
4. 測定値を入力(**1項目1行、上から順に**)
   - 数値は小数点にカンマ `12,5` でもピリオド `12.5` でも可(→「表示言語」の節)
   - **入力欄の右の `▼` か Enter で次の項目へ進む。** 最後の項目で押すとそのまま確認へ
     (スマホの数字キーボードには Enter が無いので `▼` が本命)
   - 色は4色のタイルをタップ(もう一度タップで解除)。選ぶと自動で次へ進む
   - Hábito は Horizontal / Vertical の2択
   - 一番下に **Observações**(自由記述)。測定値が1つも無くても、備考だけで保存できる
5. **Guardar e enviar → 確認画面(必ず出る)**
   - どの株に何を書き込もうとしているのかが**一覧で出る**
   - 空欄がある場合は、先に **「Esta planta não tem fruto?」(この株には果実が無い、
     ということでよいですか)** という形で**対象ごと**に尋ねる。
     雄花・雌花・果実・種子・葉は別々に判定する
   - 個々の空欄項目は、その下の「Ver os campos por preencher」を開くと出る。
     **`Comprimento da semente` のようにどの長さ・幅か分かる名前**で表示する
6. 確認して送信すると、**そのまま同じ列の次の株の入力画面に入る**
   (画面を戻る操作は要らない)。列の最後まで行くと株選択画面に戻る
   - 別の株にしたいときは、**入力画面のいちばん上の見出しをタップ**すると株選択に戻る

画面上部のバー:
- 緑 `Ligado — tudo enviado` … 全部送信済み
- 黄 `Por enviar` + 件数 … 送信待ちあり
- 黄 `A enviar… 25 de 100` … 送信中(**何件目まで進んだかが出る**)
- 赤 `Sem rede — guardado no telemóvel` … 圏外(入力は続けられる)
- `ADMIN` バッジ … 管理者モード中

## オフラインで貯めて、オンラインで自動送信

**100件くらいまとめて圏外で入力し、電波のある場所に戻ったら自動で送る**という
使い方を想定している。

- 入力は全部まず端末の中(IndexedDB)に入る。**送信の成否とは無関係に消えない**
- 電波が戻ると **Background Sync** が働き、**アプリを開いていなくても送信される**
  (Android の Chrome。iOS には無いので、その場合はアプリを開いたときに送る)
- 25件ずつに分けて送り、**1束ごとに「送信済み」を記録する**。途中で電波が切れても、
  そこまでの分は確定し、残りだけが次回に回る
- 送信は Service Worker と画面の両方から走るが、**同じ記録が二重に書かれることはない**
  (サーバーが送信IDで重複を弾く)
- 進み具合は上のバーの `A enviar… 25 de 100` と、`Registos` → `Neste aparelho` の
  ⏳ / ✅ / ⚠️ で分かる

⚠ **アプリのアンインストールと、ブラウザの「サイトデータ削除」は送信待ちを消す。**
送信待ちがある間は絶対にしないこと。

## 表示言語(PT / EN / 日本語)

既定はポルトガル語。**入口の3画面**(活性化・名前・調査選択)の右上にボタンが出る。
測定中の画面には出さない — 現場で誤って触る余地を増やさないため。

- 選んだ言語は端末に保存され、次に開いたときもそのまま
- 切り替えるのは表示だけ。**シートに保存される内容は言語に関係なく同じ**
  (`Horizontal` / `Light green`、ロット名 `India #bag01`、調査回の名前、数値の `.`)
- Plant ID・列名(r01〜r16)・ロット名の中の記号は固有名詞なので翻訳しない
- 選んだ言語は `<html lang>` にも反映するので、**Chrome が勝手に翻訳を被せてこなくなる**

> ⚠ ブラウザの自動翻訳は使わないこと。ページの文字を機械翻訳で書き換えるだけで、
> アプリの言語設定が変わるわけではない。入力画面では誤訳や表示崩れの元になる。

### 小数点はどちらでもよい

**`12,5` でも `12.5` でも同じ 12.5 として読む。言語設定には関係しない。**
ポルトガル語圏の書き方と英語圏の書き方が現場で混ざるため。

- 全角の `１２，５` も読む(日本語キーボード対策)
- 同じ記号が2回以上出てきたら桁区切りとみなす(`1.234,56` → 1234.56)
- **画面に出すときの記号は言語に従う**(ポルトガル語 `12,5` / 英語・日本語 `12.5`)
- **シートに書く値は言語に関係なく常に `12.5`**(ピリオド)

言語を足すときは `docs/i18n.js` に同じキーの塊を1つ増やし、`IDIOMAS` に1行足すだけ。
コード側の変更は要らない。⚠ 文言を足したら3言語すべてに足すこと
(欠けたキーはポルトガル語に落ちる)。

## 進捗の見方

- **調査選択画面の各カード**に「19 de 415 plantas (5%)」とバーが出る
- **Ver progresso** に**2つの見方**が並ぶ:
  **Por fileira**(r01〜r16。歩く順)と **Por linhagem**(1〜17。データシートの並び)
- **株選択画面の列ボタン**にも `19/35` と出るので、どの列が残っているか一目で分かる
- **Saltar para a próxima por fazer** … 現在地の次の未登録株へジャンプ(端まで行くと先頭へ回る)。
  **枯死株として印を付けた株は飛ばす**
- 枯死株は「未登録」にも「登録済み」にも数えず、`3 mortas` として別に表示する。
  バーは「登録済み + 枯死」で埋まるので、全部見終わったロットは 100% になる
- 圏外のときは最後に取得した進捗をそのまま表示し、「actualizado …」に取得時刻が出る。
  この端末で入力してまだ送っていない分も進捗に加算される

## 枯死株(Planta morta)

415株のうち既に枯れているものがある。**株を選んだあと、右下に小さく出る
`Marcar planta morta`** で印を付ける(めったに使わないので目立たせていない)。

- **測定の記録ではない。** シートの `Data` の **`Plant status`** 列に `Dead` と入るだけで、
  測定値の列には何も書かない。Crescimento / Descritores のどちらで印を付けても同じ扱い
- 印の付いた株は「未登録」の一覧から外れ、`Saltar para a próxima por fazer` も飛ばす
- もう一度押すと取り消せる(`† morta — desmarcar`)。`Log` には
  `Planta morta` / `Planta viva` の行が残る
- **圏外でも押せる。** ほかの登録と同じキューに入る

## 権限と修正

**2026-08-12 に方針を変えた。誰でも、誰の記録でも修正・削除できる。**
それまでは「登録した本人か管理者だけ」だったが、現場で名前や端末を変えると
自分の入力ミスさえ直せなくなるため。**誰が何をしたかの記録は `Log` に全部残る。**

- 株を選ぶと「✓ já registada por Cheia — pode corrigir」と出て、
  フォームが**前回の値で埋まった状態**で開く。ボタンは `Guardar correcção` に変わる
- 🔒(他人の記録は触れない)という表示は無くなった
- **記録の持ち主は「最初に登録した人」で固定**される(誰が直しても移らない)。
  一覧では「Cheia · corrigido por Joana」と表示される
- **管理者モード**はログイン画面の「Modo administrador」から。書き込みの可否には
  もう関係しないが、仕組みは残してある(**12時間で自動的に切れる**)
- `Log` シートには毎回1行増え、`Ação` 列に `Registo` / `Correcção` / `Eliminação` /
  `Planta morta` / `Planta viva`、`Substitui o envio` 列に修正元の送信IDが入る

## 登録の取り消し(Eliminar)

株を間違えて記録したときのための機能。**フォーム画面の一番下の赤いボタン**
`Eliminar este registo` から行う。

- **確認画面が必ず挟まる。** 消える値を一覧で見せたうえで `Voltar` / `Eliminar` を選ぶ
- 実行すると、その調査(Crescimento のそのラウンド、または Descritores)の列が
  **シート上で空になり**、その株は「未登録」に戻る
- **`Log` には `Eliminação` の行が残り、消した値もその行に記録される。**
  何を消したのかは後から必ず追える(備考も一緒に残る)
- 権限は修正と同じ。**2026-08-12 から誰でも消せる**(管理者でなくてよい)
- **`Registos` の一覧から開いた記録もこのボタンで消せる。** 以前は進捗が
  サーバーから届いていないとボタンが出ず、履歴から開くと消せなかった
- **圏外でも押せる**。他の登録と同じキューに入り、電波が戻ったときに送られる
- 取り消したあとは、別の人が改めて登録できる(所有者もリセットされる)

⚠ 消えるのは**そのアプリで扱う列だけ**だが、Crescimento の既存ラウンド
(`5 month after planting (20260511)` など)を選んで取り消すと、
**アプリを使う前からシートにあった測定値も一緒に消える**。
新しいラウンドで作業しているぶんには起こらない。

## 登録の一覧(Registos)

- **Neste aparelho** … この端末で入力した分。**圏外でも見られる**。⏳送信待ち / ✅送信済み / ⚠️エラー
- **Todos** … シートにある全登録。**誰の記録でもタップすると修正フォームが開く**
- どちらの一覧も `2 (India #bag02) · n.º 15  NBF(Tanheia)26-045` のように
  **n.º de referência で見出しを出す**
- 開いた記録は **`Voltar` でこの一覧に戻る**。修正を保存したあとも一覧に戻る
  (`Voltar` は常に「1つ前の画面」に戻る)

## 設計上の判断(要確認・変更可)

### 1. 「番号」の意味 — 解決済み(2026-08-09)

`Data` シートの **C列「No.」は種子ロット(Source)ごとにリセットされる**。
つまり列(Row)ごとの通し番号ではない。実際、r01 は 001〜035 の35株だが、
C列の No. は bag01 の 1〜30 と bag02 の 1〜5 が混在する。
**(Row, No.) の組は一意ではなく、多数の株で重複する。**

アプリは最初から「**その列の中での位置(1〜35)**」を番号として使っていた。
2026-08-09、Kaz さんの指示でこれを**シート側にも実体化**し、
**D列「No. in row」** を新設して415株分の値を入れた(A〜C の右)。

この挿入により、それまで **F〜X にあった測定列は G〜Y へ1つずつ右にずれた**。

| | 挿入前 | 挿入後 |
|---|---|---|
| 生育調査(Crescimento) | F〜K | **G〜L**(のち G〜M) |
| 形態記載(Descritores) | L〜X | **M〜Y**(のち N〜Z) |
| 新ラウンドの追加先 | Y以降 | **Z以降**(のち AA以降) |

`Codigo.gs` の `CAMPOS_CRESCIMENTO` / `CAMPOS_DESCRITORES` の `col` と
`COL_PRIMEIRO_BLOCO_RONDA` がこの並びを持っている。**シートの列を動かしたら
ここも必ず直すこと。** `tests/teste_gas.py` が実物を動かして検証している。

**⚠ 2026-08-12 に、画面で株を指す方法を C列の No.(ロット内の番号)に切り替えた。**
下の「1g」を参照。D列「No. in row」はシートにも画面にも残っているが、
選択の主役ではなくなり、確認用の表示になった。

### 1b. 株数は415、列は r01〜r16(2026-08-09 修正)

初回解析で `Data` を400行目までしか見ておらず、**398株・r15までと誤認していた**。
実際は **3〜417行目 = 415株、r16 まである**。アプリは415株に対応済み。

### 1c. 蛇行植栽(serpentina)

圃場は蛇行して植えられている。**奇数列は左端から、偶数列は右端から**1番が始まる。
`Data` の株番号は既に歩く順路どおりに振られているので、Plant ID の昇順に進めば
そのまま圃場を蛇行して歩ける。

アプリは `plants.json` の各列に `sentido`(`esq` / `dir`)を持ち、列ボタンと株カードに
矢印で表示する。この向きは元データの `layout` タブと `Data` のロット並びを突き合わせて
検証した(`tools/gen_plants.py` のコメント参照)。

### 1d. 入力は1項目1行 + 上から順送り

Kaz さんの指示(2026-08-09)で、横に2つ並べていた項目(Cnp-1/Cnp-2 など)を全部縦1列にした。
`▼` ボタンまたは Enter で次の項目へ進み、最後の項目で押すと保存・送信まで走る。
**スマホの数字キーボードには Enter キーが無い**ので、`▼` ボタンが本命の導線。

### 1e. Branch 列(2026-08-10 追加・⚠ 試験的)

Kaz さんが `Data` の Cnp-2 と Fruit bunch の間に **`Branch`** 列(枝数)を追加した。
アプリ側は `ramos`(画面表示 `Ramos`、単位 `n.º`、整数)として対応済み。

これにより測定列がもう1つ右へずれた。

| | Branch 追加前 | 追加後 |
|---|---|---|
| Crescimento | G〜L(6項目) | **G〜M(7項目)** |
| Descritores | M〜Y | **N〜Z** |
| 新ラウンド | Z以降・6列 | **AA以降・7列** |
| `Log` の列数 | 35 | **36**(`Ramos (n.º)` が16列目) |

**⚠ この項目を残すかは未定。** 戻し方は `HANDOVER.md` の「Branch を元に戻す手順」に
まとめてある。ロールバックは2コミットの `git revert` + シートの列削除2箇所で済む。

### 1f. 画面に英語を出さない(ただしロット名は例外)

調査回 `5 month after planting (20260511)` は、画面には
`5 meses após a plantação (11/05/2026)` と表示する(`app.js` の `nomeRonda()`)。
**変換は表示だけで、サーバーに送る値は元のまま。**

**ロット名だけは 2026-08-12 に翻訳をやめた**(`Índia — saco 01` → `India #bag01`)。
これは文ではなく**符号**で、種子袋やシートの記載と一字一句そろっている必要がある。
Plant ID を訳さないのと同じ理由。翻訳すると同じものを指す言い方が2通りできてしまう。

### 1g. 選ぶのは列、読むのは系統(2026-08-14 に確定)

2026-08-12 に**株を選ぶ単位を系統(種子ロット)に変えたが、8月14日に元へ戻した。**
Kaz さん曰く「**列で分かっていれば問題ない**」。ただし:

> 順番に進んでいった時に、**どの系統の何番目か**を分かるようにしてほしい。
> データシートと地図がそのように作られているから。

そこで**選ぶのは列(r01〜r16)+ 列内の番号**に戻し、**系統は画面の主役**にした。
株が決まると、株カードと入力画面の見出しの**いちばん大きい行**に出る:

```
2 (India #bag02)  n.º 15      ← 系統2番の15株目(いちばん大きい)
NBF(Tanheia)26-045
Fileira r02, n.º 10  ·  ← n.º 1 à direita
```

- 系統には**並び順どおり 1〜17** を振る。**bag08 は欠番なので `India #bag09` は 8番**
- 系統の先頭の株には `início da linhagem` の印を出す(数え間違いが起きやすい場所)
- 進捗画面は**列ごとと系統ごとの両方**を並べて出す
- 対応表は3か所に**同じ順序で**ある。片方だけ直さないこと:
  `docs/plants.json` の `lotes` / `Codigo.gs` の `LOTES` / `tests/servidor.py` の `LOTES`
  (`Codigo.gs` の `diagnostico()` が合計415になっているか点検する)

### 1i. 入力の導線(2026-08-14)

現場で「一手でも減らしたい」という要望があり、次の3点を変えた。

1. **列を押すと番号に `1` が入る。** 列は必ず1番から始めるので、その分のタップを省く
2. **株選択画面はスマホ1画面に収める。** 以前は `Continuar` が画面の下に隠れていて、
   毎回スクロールしないと押せなかった。列のグリッドを8列・テンキーを小さくし、
   `Continuar` は**下に固定**した。回帰テスト `teste.py` の [16] が
   `scrollHeight - innerHeight <= 0` を実際に測っている
3. **保存すると、そのまま同じ列の次の株の入力画面に入る。** 株選択画面を経由しない。
   列の最後まで行くと株選択に戻る。入力画面の見出しをタップすれば株を変えられる

### 1j. 保存前の確認画面(2026-08-14)

**保存の前に必ず確認画面が出る。** 以前は空欄があるときだけ出ていた。

空欄の伝え方も変えた。「果実の長さと幅が空です」ではなく、
**「この株には果実が無い、ということでよいですか」**と**対象ごと**に尋ねる。
現場の人が頭の中で答えられるのはこちらの問いだから。

対象の定義は `app.js` の `OBJECTOS`。**画面上のグループ分けとは別物**で、
例えば「果実の色」は画面では『色』グループにあるが、判定上は『果実』に属する。
雄花・雌花は1項目ずつ別の対象として扱う(片方だけ咲いていることがあるため)。
個々の空欄項目は、その下の折りたたみを開くと出る。

### 1h. 備考と枯死株の列(2026-08-12 追加)

`Data` の**いちばん右**に3列を、**見出しの文字列で探して、無ければ作る**方式で足した。
既存の列を1つも動かさないためにこうしてある(列を挿入すると測定列がずれる)。

| 見出し | 中身 |
|---|---|
| `Notes (growth)` | Crescimento の備考(最新のものが残る) |
| `Notes (descriptors)` | Descritores の備考 |
| `Plant status` | 枯死株なら `Dead`、それ以外は空 |

新しいラウンドのブロックはこの3列より右に追加される。`ehColunaDeRonda_()` が
この3つの見出しを「調査回ではない」と判定するので、ラウンド一覧には出てこない。
**全部の履歴は `Log` に残る**(`Notas` 列)ので、`Data` 側が上書きされても追える。

### 2. シートに書き込む値は英語

`Data` シートは英語のデータセットなので、選択肢は英語で保存する
(`Horizontal` / `Vertical`、`Light green` / `Medium green` / `Dark green` / `Red`)。
画面表示はポルトガル語。ポルトガル語で保存したい場合は `Codigo.gs` の
`VALOR_HABITO` / `VALOR_COR` の右辺を書き換える。

なお `Data!L2` の見出しは `Horizantal/Vertical` と綴りが誤っているが、
シートは触っていない。保存される値は正しい `Horizontal`。

### 3. Crescimento の新しいラウンド

G〜M の既存ブロック(`5 month after planting (20260511)`)は上書きしない。
新しい Ronda 名で送信すると、シートの**末尾に7列の新ブロックを自動追加**して
そこに書く。1行目にラウンド名、2行目に項目名が入る。

### 4. Data への書き込みは「最新が勝つ」

同じ株に2回送ると `Data` の値は上書きされる。ただし `Log` には毎回1行残るので、
履歴は全部追える。

### 5. Log シート

2026-08-08 に、旧44列ヘッダー(`Branch`, `Sepal Shape`, `Endocarp Rugosity` 等)を
**`Log_backup_20260808` タブに退避**したうえで、Data の測定19項目に合わせた**35列**に
置き換えた。旧ヘッダーは行1のみでデータ行は無かったため、失われたデータは無い。

`Log` の列構成は Data の列位置に依存しないので、2026-08-09 の D列挿入では変わっていない。
ただし `Levantamento` 列に入る文字列は `Crescimento (G-M)` / `Descritores (N-Z)` に変わった。
読み戻しは先頭一致(`Crescimento` で始まるか)で判定しているので、旧表記の行も正しく読める。

構成: `Data/hora (aparelho)` / `Data/hora (servidor)` / `Registado por` / `Ação` /
`Levantamento` / `Ronda` / `Plant ID` / `Fileira` / `N.º na fileira` / `N.º na folha` /
`Lote` / `Linha em Data` + 測定20項目 + `ID do envio` / `Substitui o envio` /
`Aparelho` / `Estado` + `Notas` / `Estado da planta` / `N.º de referência`。
**計39列。**

**⚠ 2026-08-12 に足した3列は、いちばん右(`Estado` の後ろ)に置いてある。**
本当は値の隣に置きたかったが、`Log` には既に記録された行があり、途中に列を挟むと
その行の右側の意味が全部1つずれる。**`Log` に列を足すときは必ず末尾に足すこと。**
`N.º de referência` は端末が送ってきた値ではなく **株番号から計算している**ので、
この機能より前に作られた送信待ちの記録にも正しい番号が入る。

`Ação` が `Correcção` の行は修正で、`Substitui o envio` に修正元の送信IDが入る。
`Estado` が `ERRO: …` の行は書き込みが拒否された記録(値の不正など)。

### 6. 送信の仕組み(2026-08-14 に作り直し)

**同じ送信ロジックが2か所にある** — `docs/app.js`(画面から)と `docs/sw.js`
(Service Worker から)。ビルド工程が無いので共有できない。
**サーバーに送る中身を変えるときは必ず両方直すこと。**

- 画面側: 保存時・オンライン復帰時・前面に戻ったとき・60秒ごと
- Service Worker 側: **Background Sync**(`sync` タグ `enviar-fila`)。
  電波が戻れば**アプリが閉じていても走る**。失敗したら `waitUntil` を reject して
  ブラウザに再試行を任せる
- Service Worker には localStorage が無いので、**エンドポイントとトークンを
  IndexedDB の `config` ストアに写している**(`espelharConfig()`)。
  **IndexedDB はバージョン 2**。`envios` ストアは名前もキーもそのままなので、
  旧バージョンで作られた送信待ちはそのまま生き残る
- 送信の進捗は Service Worker から `postMessage` で画面に伝える
